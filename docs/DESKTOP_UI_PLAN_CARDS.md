# 桌面端「卡片化」界面改造计划

> 起因：`ui_reference/01.JPG` … `12.JPG` 是用户手绘的 12 张桌面端 UI 草图。
> 它们描述的不是微调，而是把桌面端从"三栏 IDE 外壳"改成
> **卡片 + 悬浮播放卡**的形态：左栏只剩用户卡与歌单卡，主页由若干张卡片组成，
> **播放条从贴底通栏变成中栏里的一张卡**，播放详情页砍掉队列栏，
> 歌单详情从卡片网格变成**紧凑歌曲行**。
>
> 施工范围：`apps/desktop/src/renderer/**` + `apps/desktop/src/renderer/index.html`
> （结构重排）+ `main.cjs` / `preload.cjs`（仅阶段 0 的窗口控制），
> 外加受影响的探针驱动与 `scripts/verify-*`。
> **主进程的其它逻辑 / IPC / DB / `packages/core` 一行不动。**
>
> 与既有文档的关系：
>
> - [`DESKTOP_PLAN.md`](./DESKTOP_PLAN.md)：功能与主进程计划，本轮不动。
> - [`DESKTOP_UI_PLAN.md`](./DESKTOP_UI_PLAN.md)：阶段 0–5（设计系统 + 第一轮卡片化）。
> - [`DESKTOP_UI_PLAN_STAGE6_PROGRESS.md`](./DESKTOP_UI_PLAN_STAGE6_PROGRESS.md)：阶段 6 / A–D。
>   **本文件是它的下一轮**，会**推翻**其中三处结论（§1.3 记录理由与依据）：
>   正在播放页三栏 → 两栏；播放条通栏 → 中栏卡片；曲目卡片网格 → 紧凑行卡。

---

## 0. 一句话目标

**把「窗口分区」换成「卡片」。** 屏幕上每一块功能都是一个圆角面
（`--surface-container` + `--r-lg`，不描边），卡片之间靠留白分层；
左栏是"我"，中栏是"我在看的内容"，中栏底部是"正在播放"这一张卡。
窗口里不再出现通栏分割线，也不再出现同一个功能的第二个入口。

> ⚠️ **队列到底住哪**（这是本轮最需要想清楚的一处冲突）：
> 草图 `06` 要"弹出浮层"，而现有实现是"右栏的队列面板"，两者都要成立。
> 做法：**队列 DOM 仍然只有一份**（`#queue-list`，禁止复制），
> 平时住右栏 `#queue-slot`；点播放卡的「播放列表」按钮时，把**同一个节点**
> 搬进浮层容器 `#queue-popover-slot`，关闭时搬回。
> 这与现有 `placeQueue(showNow)` 完全同构，只是多一个槽位。
>
> 复制一份会让 `data-queue-index` 重复 → 探针计数翻倍、拖拽落到错误的树上
> （`renderer.js:221-229` 的注释已经踩过）。**探针现在明确断言
> `#queue-list.parentElement.id` 只能是 `queue-slot` 或 `nowplaying-queue-slot`**
> （`ui-probe-driver.cjs:2415/2485/2540`）——本轮要把这个"允许集合"扩到三个槽位。
>
> 另一个硬约束：`.nowplaying__columns.is-queue-hidden .nowplaying__card--queue{display:none}`
> **不能改成条件渲染/卸载节点**，否则隐藏态下 `[data-queue-index]` 会掉到 0。

## 2. 技术地基（改造前必须知道的事实）

> 本节是从代码里核出来的**当前**事实（行号已对齐），下一节的规格全部建立在此之上。

### 2.1 设计令牌：真相在哪、怎么下发

链路：`packages/design-tokens/src/index.ts`（TS，无 dist）
→ 构建期 `scripts/build-core.mjs` 打成 `apps/desktop/build/tokens.cjs`
→ **主进程** `apps/desktop/src/theme.cjs` 生成一段 CSS 文本
→ IPC `theme:describe` / `theme:changed`
→ `renderer/theme.js` 写进 `<style id="bb-theme-vars">`（`document.head.appendChild`，

### 5.3 断言写法纪律（沿用阶段 6 的四条教训）

1. **只断言"元素存在"不够** —— 要走真实的打开路径（点按钮、读结果）。
2. **描述字符串里的检查不是检查** —— 判断必须写进**条件**，不能只写进消息。
3. **读数据源，不要猜选择器** —— 查一个不存在的属性会恒为 0 → 永远"已覆盖"。
4. **喂给驱动的脚本要短而平** —— `evaluate` 模板里塞三元 + 多行链式会让渲染进程
   解析失败且**不给行号**。

> 另有一条本轮必须遵守：**改 DOM 之前，先跑一遍"未改探针"的回归，确认它会变红。**
> 不变的绿说明探针压根没在看那个东西（假绿），此时改选择器只是把假绿延续下去。

### 5.4 「UI 不重叠」的通用巡检（草图 12 的硬性要求）

在 `ui-probe-driver.cjs` 末尾新增一条**通用**断言，对所有主要视图跑一遍：

```js
// 对每个视图的"卡片清单"两两做矩形相交判定；允许 1px 容差（亚像素）
const rects = cards.map((el) => ({
	id: el.dataset.testid ?? el.className,
	...el.getBoundingClientRect(),
}))
const overlaps = []
for (let i = 0; i < rects.length; i++)
	for (let j = i + 1; j < rects.length; j++) {
		const a = rects[i],
			b = rects[j]
		if (
			a.right > b.left + 1 &&
			b.right > a.left + 1 &&
			a.bottom > b.top + 1 &&
			b.bottom > a.top + 1
		)
			overlaps.push([a.id, b.id])
	}
```

覆盖：左栏两张卡、`.main` 的卡片栈、播放卡、详情页两栏。
**浮层允许覆盖，但必须 `z-index` 明确且点外部可关** → 浮层单独断言，不参与相交检查。
同时断言**没有元素溢出 `.app`**（`rect.right <= app.right + 1`）——
阶段 0 之前 `.share-view` 就踩过"内容溢出压到状态栏"。

## 9. 实施记录（P0–P12 的结论）

> 这一节是**给下一个窗口的交接件**：它不知道我们聊过什么，读完这一节应该能
> 接手。逐阶段的详细过程（每次的失败与原因）在
> `docs/DESKTOP_UI_PLAN_CARDS_PROGRESS.md`，这里只留**结论与取舍**。

### 9.1 与草图的偏差（有意为之，写下来免得被"改回去"）

| 草图/原文                               | 实现                                        | 为什么                                                                                                                                    |
| --------------------------------------- | ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 播放卡右侧"额外增加控件按钮"            | 只保留**一颗**（队列），模式按钮在右侧      | 同一个动作两个入口是这份施工单一直在删的东西；参考图里那颗队列按钮在传输条上                                                              |
| 歌单详情 = 页头 + **横长条**行（图 09） | 页头 + `.song-row` 行；**内嵌预览**仍是表格 | 旧的 `library.js` 注释写着"整页 = 卡片网格"。用户当时反对的是"同一件事两套长相"，不是"必须是卡片"；内嵌预览只有几百像素宽，行会退化成方块 |
| 播放详情"背景模糊封面主色"              | **主色**（径向渐变），**不模糊**            | 草图后半句就是"不要模糊"                                                                                                                  |
| 音乐库"播放列表"页签                    | 仍是**卡片网格**（不是行）                  | 那一屏是"选歌单"，卡片更合适；只剩歌单详情是"选歌"                                                                                        |

### 9.2 三个"看不见的"坑（都花了很久，值得先读）

1. **`evaluate` 注入脚本里的反引号**。探针的注入脚本写在模板字符串里，
   注释里出现反引号会把字符串提前截断 —— 探针**从那一节崩掉**，
   而汇总打印的是**上一轮的旧报告**（失败详情里的字符串在仓库里搜不到）。
   本轮同类问题出现 **4 次**。
   **对策**：`pnpm check:probes` 会静态扫这个问题；看到"失败信息与刚改的
   代码对不上"时，**先查报告/截图的时间戳**。
2. **DOM 里"元素在、但点不到"**。最常见的原因不是选择器写错，而是
   - 被别的元素盖住（`.content` 与互斥视图钉到同一网格行）；
   - 点击落空（元素在旧页签的 DOM 里）。
     本轮的 `#content` / `#view-nowplaying` 重叠就是这样：给互斥视图钉
     **同一行号**会让 DOM 靠前的那个画在上面。
3. **`requestAnimationFrame` 在隐藏窗口里不会被调度**。探针窗口是
   `show: false`，所以任何"下一帧再加类"的写法在探针里**永远不执行**
   （界面表现为"点了没反应"，而状态已经改了一半）。用 `setTimeout(0)`。

### 9.3 布局：中栏最终是 flex，不是网格

这一块改了四次才定下来，结论是**别用网格做纵向流**：中栏的直接子元素
个数一直在变（顶栏 / 搜索行 / 标题 / 页签条 / 收藏夹工具条 / 内容区 /
三个互斥视图 / 浮层 / 播放卡），而网格自动布局**不报错、只安静地摆错**
（顶栏吃掉整屏、播放卡跑到页面标题那一行、列表溢到播放卡下面）。

现在：`.main` 是 flex 纵向；页面内容全在 `.main-stack` 里
（`flex: 1 1 auto` + `overflow-y: auto`，**唯一**会滚的一层）；
播放卡 `flex: none` 钉在底部。网格只留 `.app` 那一层。

### 9.4 图标尺寸：只有一处真相

原来两套：`material-symbols.css`（生成物）写死 `16/20/24/40`，
而 `style.css` 的令牌是 `14/16/20`。同一个 `icon--md` 与 `--icon-md`
差 4px，改令牌时图标纹丝不动。

现在字体那一层读令牌（`var(--icon-*, 兜底)`），探针里有断言钉住
"档位类的 `font-size` 必须等于同名令牌"。

### 9.5 本轮**没做**的（下一轮候选）

- 「真·最近播放的歌单」（需要新表 + 播放埋点）。
- `renderer.js` 每帧推歌词位置的节流（约 4Hz）。
- 移动端与 `packages/design-tokens` 的数值对齐（本轮只改了渲染层的用法）。
- `.track-table` 那套表格样式**保留**：内嵌预览与历史表还在用，
  只有真正的死规则（`.favorite-list*`、`.track-grid`）被清掉了。

### 10.3 一处**行为变化**（不是重构，是语义变了）

`toggleQueuePopover()` 原来会 `if (currentView !== 'nowplaying') setNowPlaying(true)`
—— 即"呼出播放列表"顺带把你送到播放详情页。那在"队列的主家是右栏"时说得通
（"呼出"被理解成"去那一页"）。

右栏删掉之后，浮层成了播放列表**唯一**的形态，于是它**不再换页**：
你在音乐库按 `Ctrl+Q`，浮层就在音乐库弹出来。换页反而成了噪音
（用户只想看一眼队列，不想离开当前页）。

`showMainPane()` 里那句"换页就收起浮层"也跟着从 `if (!showNow)` 变成无条件 ——
因为现在**没有**哪一次切页是浮层自己发起的了。

### 10.4 两处**代价**（写下来，免得以后被当成 bug 修）

1. **没有「跳到搜索页」的独立入口**。搜索框在主页 / 音乐库 / 搜索页顶部常驻，
   输入即搜；但"我在设置页想直接去搜索"这条路没有了（要先切回音乐库）。
   这是用户确认的取舍。
2. **材质档位（none / blur / gradient）现在只影响弹窗**。顶栏是唯一常驻的
   `.material` 表面，删掉之后只剩登录弹窗还在用 —— 设置 › 外观 里那三档
   在正常使用中**看不出区别**。要么把 `.material` 挪到别的常驻表面
   （播放卡？浮层？），要么把这一档设置一起删掉，这是**下一轮**要拍的板。
   探针的材质断言已经跟着改到 `.modal.material`（对隐藏元素 `getComputedStyle`
   照样返回计算值，所以不必真的把弹窗打开）。

### 10.6 这一轮踩到的坑

**一次性重构脚本里"改副本"和"最后统一写回"不能混用。** 第一版脚本在同一个
文件里既有 `L.splice(...)`（改内存里的行数组，最后统一 `write`），又有
`write(p, text)`（在中间直接写改好的整段文本）。后者被最后那次 `write`
**原样覆盖**掉了 —— 脚本报告"✓ 三处注释已更新"，`grep` 却发现三处都是旧文案。
教训：**脚打印的"✓"只证明它执行过，不证明它的结果还在文件里**；
改完立刻 grep 一次最终状态，比相信脚本的回显可靠。

（另一个坑与阶段 0–8 同源：注入脚本的模板字符串里不能出现反引号。
这次又踩了两次 —— `pnpm check:probes` 一次全抓出来了。改完必须跑它。）

## 11. 收尾追加之二：主页按原型重做

> 用户接着提了两件事：**「当前没有一个明显的返回主页的按钮」**（在左栏歌单卡
> 里加一条「首页」）与**「主页太混乱了，请 1:1 按照 prototype 重做」**
> （但「听歌频率」那一块保留原来的 GitHub 贡献墙样式）。这一节是结果。

### 11.1 左栏加「首页」入口

顶栏删掉之后，**「回主页」在界面上没有显式入口**了 —— 点左栏顶上那张
「BBPlayer」用户卡确实能回主页（它一直是 `data-nav="home"`），但那是一张**卡**，
看起来像品牌 / 账户区，不像"一个可以去的地方"。

于是在歌单卡页头、**「收藏夹」上面**加了一条同规格的 `.sidebar__entry`
（用户圈了「收藏夹」并指定了位置）。页头因此从"一行"变成"一列两行"
（`.sidebar__card-head { flex-direction: column }`）—— 横着排的话两个入口
会在 240px 里各被压到一半宽、文字被省略号吃掉。

顺带修掉一个**真 bug**：`activateNav` 用
`event.target === event.currentTarget` 判"是不是最内层入口"，而入口按钮里有
`<span class="icon">` —— **点在图标那一小块上时那次点击会被整个丢掉**
（表现是"点图标没反应、点旁边的字就行"）。改成 `closest('[data-nav]')`
再比较。探针里加了一条"点图标也能回主页"的断言钉住它。

### 11.2 主页：从"卡片 + 下沿一块"回到一张卡片

| 项                  | 改前                                                   | 改后（原型）                                                                          |
| ------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| 最近播放            | 内容卡**外面**一条独立下沿的左半（`#home-strip`）      | 内容卡**里面**，顶部左右分栏的左半                                                    |
| 快捷入口            | 同一条下沿的右半，**3 张方块卡**（48px 圆图标 + 文字） | 分栏的右半，**4 张胶囊**（22px 圆图标 + 文字）：最近播放 / 继续收听 / 收藏夹 / 音乐库 |
| 竖分隔线            | 下沿里那个 `__divider`                                 | 分栏的**网格列**（`1fr 1px 1fr`），两栏不等高也自动拉满                               |
| 区块标题行          | 标题 + **下面**一行灰字说明                            | 标题 + 推开 + **右侧**说明（说明不另起一行）                                          |
| 播放历史            | `.view-head` 大标题 + 页签条 + **表格** + 播放全部按钮 | 页签 + 汇总 + 「播放全部」**都在标题行里**，下面是**歌曲行**                          |
| 「次数 / 上次听到」 | 表格里两列（页签切换会换一组列）                       | 行右侧**同一格**按页签换内容（`data-kind=count/position/duration`）                   |
| 相对时间            | 表格最后一列「最近播放」                               | 并进歌手那一格（「初音未来 · 3 天前」）                                               |

`#home-strip` 这个常驻容器、`bbLibrary.setHomeStrip()`、以及 `.home-strip*`
那一整套 CSS **整条删掉**了。

⚠️ 主页历史行**不给「⋮」**：历史不是可编辑的集合，摆一个点了没反应的按钮
正是这份施工单一直在删的东西。为此加了一条 `.song-row--no-more`
（去掉那一列，否则右侧空出一条 28px 的缝）。

### 11.3 顺手修掉的两个**既有**缺陷

1. **热力图横向溢出 53px**。`heatmap.js` 算格子尺寸时写的是
   `floor((available - gutter) / weeks) - 3`（减一个**写死的 3**），
   而下面按 `cell >= 14` 把列间距选成 **4** —— 每列多占 1px，53 列就是
   53px 的横向溢出：热力图下面挂着一条横向滚动条，而"格子是方格 / 每格带日期"
   那些断言全绿（它们不看容器）。现在按**真实间距**试算（先 4 再 3），
   保证 `gutter + weeks * (cell + gap) <= available`。
   ⚠️ 这条是在**巡检截图**里看出来的，不是断言抓到的 —— 又一次"能过断言的东西
   不等于能看的东西"。
2. **`.home-recent--empty` 看起来像一个空的输入框**。空态复用了
   `.home-recent` 的排布，而那一层 `background + border` 是给"有一条可以点的
   最近播放"用的。空态现在不画那张"卡片脸"。

### 11.5 一个**工具性**的坑（值得单列）

**隐藏窗口里"滚动 + `capturePage`"会拍到新旧两层混在一起的画面。**
`verify:desktop:ui` 的窗口是 `show: false` 的，为了拍主页最下面的
「播放历史」，我先滚到最底再截图 —— 截图里历史那几行**画在听歌频率上面**，
看起来像布局重叠。而同一时刻的几何断言量出来四块规规矩矩地排着
（178–298 / 322–508 / 532–792 / 816–1100），也就是**布局没问题、截图在骗人**。

处置：把"滚动截图"这件事交给 `verify:desktop:tour`（那边窗口是可见的，
`02c-library-scrolled-head` 一直是干净的），并在 `ui` 探针里留一句注释说明
为什么这里**不**拍滚动的图。教训与 §9.2 的第 3 条（`requestAnimationFrame`
在隐藏窗口里不跑）是同一类：**隐藏窗口的渲染行为与真实窗口不同，
拿它当"人眼"用要留个心眼**。
